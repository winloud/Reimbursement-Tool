## 目标

- [x] 新增与出差报销相互独立的常规报销单，支持无票报销和有票报销两种创建后不可切换的模式。
- [x] 常规报销沿用现有状态、附件、发票确认和本地数据安全能力，并使用独立列表、PDF 模板分派和字段映射。
- [x] 依据正式空白扫描件完成矢量重绘与毫米坐标校准；扫描原版仅裁切顶部 `105.13 mm`，不得缩放。
- [x] 修复报销 PDF 下载链路；允许 IDM 等工具接管，未接管时由桌面浏览器选择保存路径。
- [x] 依据行程时间线原型重构差旅与常规报销填报页：共享块卡/折叠行、差旅行程时间线，以及浅灰摘要行 + 白色抽屉层级。
- [ ] 完成常规报销单 100% 比例实物打印验收。

## 范围

- 本轮包含：常规报销数据结构与兼容迁移、逐项目凭据/发票、独立列表与汇总卡、一级侧栏导航、PDF 字段映射和模板分派。
- 无票模式按项目录入日期、名称和金额，凭据支持 PDF/图片且不作为提交门槛；单据张数按附件页数统计。
- 有票模式按项目上传并确认发票，金额取已确认发票合计，单据张数按发票记录统计。
- 常规报销不包含部门、出差事由、行程、补贴、预支和差旅看板统计。
- 正式扫描件到位前完成可独立验证的数据、接口、界面和 PDF 逻辑链路；正式模板已按扫描原版物理尺寸重新校准，仅剩实物打印验收。
- 填报页采用统一块卡语法；差旅行程按时间线显示补贴区间，其他费用类别和常规项目使用浅灰摘要行、白色展开抽屉，抽屉内发票卡与上传槽保持浅灰第三层。
- 差旅和常规报销的单张、批量 PDF 与完整数据包均通过可重复访问的真实短时 URL 下载；Chrome 独立配置和 WebView2 负责默认保存行为，备份和诊断包等 Blob 下载保留空内容与延迟释放保护。
- 本轮不包含：未经用户明确授权，不主动同步或部署 Linux 服务器，也不执行远端发布。
