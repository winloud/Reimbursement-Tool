# ADR 0006：常规报销与差旅报销共用报销单生命周期

## 状态

已采纳。

## 背景

v1.4.0 需要在既有差旅报销之外增加常规报销，并继续复用草稿、核对、提交、报销、回收站、数据导入导出和附件安全能力。现有差旅费用项目以费用类别字符串关联发票，不适合常规项目的改名、重名、排序和逐项目凭据。

## 决策

- `ExpenseReport` 继续作为统一聚合根，通过 `report_type` 区分 `travel` 和 `regular`；常规报销再用不可变的 `regular_mode` 区分 `no_invoice` 和 `invoice`。
- 历史数据和缺少类型字段的旧数据包一律解释为差旅报销，既有差旅字段、金额计算和状态语义保持不变。
- 常规明细使用独立的稳定 ID 子表，不复用按类别寻址的差旅 `ExpenseItem`。发票和报销凭据分别通过可空外键关联常规明细。
- 常规无票金额由明细手填，单据张数由逐项目凭据页数计算；常规有票金额和张数由该明细下已确认发票计算。
- PDF 入口继续共用，由报销单类型显式分派模板和字段映射；正式常规模板缺失时返回明确业务错误，不回退到差旅模板。

## 影响

正向影响：

- 状态、回收站、批量操作和安全备份无需维护两套聚合生命周期。
- 常规项目可以安全改名、重名和重排，附件顺序不依赖显示名称。
- 旧数据通过默认类型和增量迁移保持兼容。

代价：

- 报销单服务、导入导出、完整性检查、统计和 PDF 生成都必须按类型分派。
- 数据结构与数据 ZIP schema 需要同步升级，并增加常规明细及关联外键检查。
