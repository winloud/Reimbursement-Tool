# ADR 0007：行程日期按完整日期存储，月日降级为派生值

## 状态

已采纳。

## 背景

差旅行程原本只存 `depart_month/day` 与 `arrive_month/day`，纸质表单也只填月日。年份由前后端各自的启发式推断：以报销单日期为锚点，首段偏离超过 180 天回退一年，后续段的月日一旦回退就加一年。推断规则前后端必须逐字对齐，跨年行程（如 12/30 出发、1/2 到达）只能靠"月日回退"猜测，同一批行程跨越两个年份时容易判错，且用户在界面上看不到年份、无法纠正。

填报页把行程日期改为日历输入后，用户实际选择的就是完整日期；若仍只存月日，用户选定的年份会在保存时丢失，跨年问题并未解决。

## 决策

- `trips` 新增可空的 `depart_date` / `arrive_date`，作为行程日期的唯一真源。
- `depart_month/day` 与 `arrive_month/day` 保留为派生列，写入时由日期拆出。PDF 表单填充、数据导出和统计的读取路径保持不变。
- `infer_trip_date_ranges`（后端）与 `buildTripDateRanges`（前端）优先使用已存日期；两者仍保留原推断规则，只用于缺日期的历史行程，且已知日期会把后续推断的年份重新对齐。
- 升级时一次性回填：按原推断规则算出年份写入日期列，含回收站中的报销单。日期本身矛盾（如同日到达时刻早于出发时刻）的报销单整张跳过，保持空日期并由编辑页提示补填，不阻断启动或导入。
- 数据包 schema 版本保持 v6：新增字段可选，旧包缺失时导入后按同一规则回填，新包对旧版本程序仍可读（月日字段照常导出）。

## 影响

正向影响：

- 跨年行程由数据本身表达，补贴天数、统计区间和年份提示不再依赖猜测。
- 铁路电子客票导入可直接写入车票上的完整日期，不再丢年份。
- 填报页可以直接用日历控件，与常规报销单的发生日期输入方式一致。

代价：

- 推断逻辑没有删除，仍需与前端保持一致，直到历史数据全部带上日期。
- 写入路径（表单保存、票据导入、数据包导入）都必须同时维护日期与派生月日，任何新的写入点遗漏日期都会退化回推断。
