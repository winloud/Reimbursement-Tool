# 0002 采用便携式安装根目录承载 ZIP 桌面升级

## 状态

已接受。

## 背景

当前 Windows 桌面版通过 ZIP 分发，用户解压后运行 `报销管理\报销管理.exe`，运行数据保存在 EXE 同级目录。旧的“新旧目录并行 + 手动复制 data/uploads/vendor”方案安全，但用户需要理解新旧目录和运行态目录，升级体验不够直接。

Linux 服务器部署仍是源码、systemd 和 Nginx 路线，当前属于验证路线，不应为了桌面 ZIP 升级把两者强行合并成同一执行机制。

## 决策

Windows 桌面版采用便携式安装根目录：

- 用户长期只认一个 `报销管理\` 文件夹。
- 根目录 `报销管理.exe` 是 launcher。
- 真实 PyInstaller 程序放在 `报销管理\versions\<version>\`。
- 根目录 `current-version.json` 决定 launcher 启动哪个版本。
- 数据库、附件、日志、浏览器配置、窗口状态继续保存在安装根目录。
- 程序内更新只安装新版本目录并切换 `current-version.json`，不删除旧版本目录。

桌面 app 和 Linux server 暂不共用同一升级执行链；两者只共享发布版本号、升级前备份、manifest 校验和可回滚原则。

## 影响

- 新发布 ZIP 结构会变化，但用户双击入口仍是 `报销管理\报销管理.exe`。
- 首次从旧 ZIP 结构迁移到便携根目录时，仍可使用本地升级脚本复制运行态数据。
- 后续桌面更新可在程序内上传新版发布 ZIP，安装后重启生效。
