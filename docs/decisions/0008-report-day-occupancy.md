# ADR 0008：以持久日期占用分配跨报销单补贴天数

## 状态

已采纳。

## 背景

原补贴天数算法只合并单张报销单内部的出差区间。同一报销人在多张报销单中出现重叠自然日时，每张单都会重复计算该日。若每次从全部报销单重新推导优先级，修改较早草稿又会反向改变已经保存甚至已提交的其他单据，不利于核对和审计。

## 决策

- 新增按 `report_id` 持久化的日期占用记录，以去除首尾空格后的报销人和自然日作为唯一键。
- 当前草稿保存时先释放自身旧占用，再从现有“起 / 止”算法得到候选日期并取得仍空闲的日期；实际取得数作为自动补贴天数。其他报销单不随本次保存重算。
- 人工核定报销单仍占用候选日期，但保持不输出补贴天数；删除释放占用，恢复重新取得当前空闲日期。状态流转保留占用；退回草稿会持久标记一次待刷新，并在下一次内容保存时重新取得。
- 日期释放后不自动转移，其他草稿只有在下一次保存时才能取得。数据库唯一约束保证多窗口竞争时每个“报销人 + 日期”只有一个所有者。
- 日期占用是业务状态而非临时缓存：完整数据包保存具体占用日期；旧数据仅在升级或旧格式导入时按报销单原始编号顺序初始化一次。
- 看板金额、单数、费用分布、出差人天、趋势和热力图全部包含未删除草稿；草稿金额与已核对、已提交金额一并归入待报销，已报销金额仍只包含已报销记录。

## 影响

正向影响：

- 重叠自然日只计入一张报销单，重新打开当前草稿不会把自己的日期误判为冲突。
- 编辑、删除或恢复草稿不会静默改写其他单据，日期归属可通过数据库和数据包稳定恢复。
- 编辑器与看板共享同一占用真源，不再分别推断跨单据重叠。

代价：

- 行程候选日期和实际占用日期成为两个概念，所有会改变行程或报销人的写入入口都必须同步维护占用。
- 释放日期不会立即补给另一张重叠草稿；该草稿需再次保存才会取得。
- 数据库和完整数据包结构升级到 v7，导入、备份和完整性检查必须覆盖新表。
