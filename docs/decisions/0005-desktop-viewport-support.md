# ADR 0005：桌面端视口是唯一正式支持目标

## 状态

已采纳。

## 背景

本工具面向 Windows 本机桌面使用，主要环境是高分辨率显示器配合系统缩放。继续同时维护手机和窄窗口布局，会为数据表、行程卡片、汇总栏和导航增加独立组件形态、断点与视觉回归成本，但这些场景不属于当前实际交付目标。

## 决策

- 正式支持 CSS 逻辑视口宽度不低于 `1280px` 的桌面窗口；断点仍按 CSS 逻辑宽度判断，不按物理分辨率或 `devicePixelRatio` 判断。
- `1536×864` 作为 4K 显示器 Windows 250% 缩放的主要布局验收尺寸；布局改动仅在风险相关时补充 `1280×720` 的支持下限检查，不再常规执行手机和更窄视口的视觉回归。
- 低于 `1280px` 的窗口只提供尽力展示，不承诺无换行、无溢出或完整交互，也不作为发布阻塞条件。
- 新功能无需新增移动端卡片、触摸专用交互或窄屏专用断点；现有响应式代码可以保留，不为了清理本身进行大范围删除或重构。
- 桌面支持范围内仍必须保持键盘可达、用途提示、可读字号、稳定点击区域和合理的系统缩放表现。

## 影响

正向影响：

- 产品和测试资源集中到实际使用的 Windows 桌面场景。
- 数据密集页面可以优先保证列宽、行高和操作密度，不再为手机形态牺牲桌面认知效率。
- 减少仅为窄屏存在的分支、组件变体和重复视觉回归。

代价：

- 手机、平板和过窄桌面窗口可能出现截断、换行或横向溢出，相关问题不再保证修复。
- 若未来恢复窄屏支持，需要重新定义目标设备、交互形态和独立验收矩阵，并以新的 ADR 取代本决策。
