# 待办需求池

本文档记录暂不进入当前版本范围、后续版本再评估的需求。

## 下个版本候选

### 增量包和增量更新

状态：待确认。

背景：

- 当前每次发布都是全量 ZIP，每个包解压后都可以独立运行。
- 增量包可以减少更新包体积，但会增加校验、回滚和版本链路复杂度。
- 建议继续保留全量 ZIP 作为主交付方式，增量包只作为程序内更新的加速通道。

初步实施计划：

1. 发布 manifest 增加完整文件清单：路径、大小、sha256、版本、数据结构兼容范围。
2. 打包脚本新增增量模式：指定基础版本和目标版本，对比文件清单，只打包新增/变更文件，并记录删除文件列表。
3. 增量包预览：校验本机是否已安装基础版本，校验基础版本文件 hash 是否匹配；不匹配时拒绝并提示使用全量 ZIP。
4. 增量安装：先创建 `pre_update_*.zip`，复制基础版本目录到 staging，再应用增量文件和删除列表，完整 hash 校验通过后移动到 `versions\<target>`。
5. 原子切换：只有目标版本目录完整验证后才更新 `current-version.json`；失败则删除 staging，不影响当前版本。
6. UI 复用“选择更新 ZIP”入口识别全量/增量包，增量包展示“基础版本 -> 目标版本、变更文件数、节省体积”。
7. 第一期只支持“基础版本精确匹配”的增量包，不做跨多个版本的自动补丁链，降低回滚和数据风险。
