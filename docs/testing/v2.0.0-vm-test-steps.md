# v2.0.0 Win11 虚拟机测试步骤

> 面向执行的操作手册。验收结论记入 `v2.0.0-tauri-acceptance.md`，本文只写怎么做。
> 每完成一个大项，把结论回填到验收记录的对应勾选项。

## 0. 准备

### 0.1 虚拟机

- Windows 11 x64，全新安装，**不要**登录你的常用账号
- 装好系统、打完更新后**立刻打一个快照**，命名 `clean`
- 之后每做完一个大项就恢复到 `clean`，避免上一项的残留影响下一项

### 0.2 把文件拷进虚拟机

从宿主机拷这些到虚拟机桌面（共享文件夹或拖拽都行）：

| 文件 | 宿主机位置 |
|---|---|
| 安装包 | `src-tauri\target\release\bundle\nsis\报销管理_2.0.0_x64-setup.exe` |
| 旧便携目录副本（测迁移用） | 你自己的旧版 `报销管理` 文件夹，**复制一份**，别用原件 |

### 0.3 两个常用命令

**查残留进程**（每次关闭程序后都跑一次，正常应该没有任何输出）：

```powershell
Get-Process | Where-Object { $_.ProcessName -like '*报销管理*' -or $_.ProcessName -like '*reimbursement*' }
```

**看日志**（出问题第一时间看这里）：

```powershell
Get-Content "$env:LOCALAPPDATA\com.winloud.reimbursementtool\runtime\logs\sidecar.log" -Tail 50
```

## 阶段 A：现在就能做（不需要签名密钥）

### A1 全新安装

1. 双击 `报销管理_2.0.0_x64-setup.exe`
2. **留意 SmartScreen**：大概率弹"Windows 已保护你的电脑"。记下弹没弹、原文是什么。
   点"更多信息" → "仍要运行"继续
3. 按提示装完，全程**不应该**要求管理员权限
4. 检查开始菜单有"报销管理"，桌面有快捷方式
5. 检查装到了 `%LOCALAPPDATA%\Programs\` 下（当前用户安装，不是 `C:\Program Files`）

> ⚠️ 如果这一步就失败，先看虚拟机是否联网——常规包缺 WebView2 时要联网自动装。

### A2 首次启动与"新建空白数据"

1. 从开始菜单启动
2. 应该出现引导页，两个按钮：**新建空白数据** / **从旧便携版迁移**
3. 点"新建空白数据"
4. 等待进入业务界面（首次启动 sidecar 要几秒）
5. 确认数据目录已建：

```powershell
dir "$env:LOCALAPPDATA\com.winloud.reimbursementtool\runtime"
```

应该看到 `data`、`logs` 等目录，`data\expense.db` 存在。

6. **查 sidecar 子进程**（程序开着的时候）：

```powershell
Get-Process reimbursement-sidecar -ErrorAction SilentlyContinue | Select-Object Id, ProcessName
```

应该有一个。

### A3 生命周期与进程回收

逐条做，每条做完都跑 0.3 的查残留命令，**都应该无输出**：

| # | 操作 | 期望 |
|---|---|---|
| 1 | 正常点窗口右上角 × 关闭 | 无残留 |
| 2 | 再次启动，然后任务管理器强杀 `报销管理.exe`（模拟崩溃） | sidecar 也被回收，无残留 |
| 3 | 程序开着的时候，再双击一次快捷方式 | 不开第二个窗口，原窗口被提到前台 |
| 4 | 程序开着，任务管理器强杀 `reimbursement-sidecar.exe` | 界面报错或失去响应（可接受），关闭后无残留 |

### A4 业务烟测

在程序里依次做完，每步都要真的成功：

- [ ] 新建一张出差报销单，填基础信息
- [ ] 录入行程（至少两段）
- [ ] 上传一张 PDF 发票，确认识别出的金额
- [ ] 上传一张图片发票（截图即可），确认金额
- [ ] 点预览，PDF 能正常显示
- [ ] 状态从草稿 → 已打印 → 已报销
- [ ] 列表页筛选能用
- [ ] 看板数据跟着变

### A5 下载（重点测边界）

每一项都要用**原生保存对话框**（不是浏览器下载栏）：

| 场景 | 怎么做 | 期望 |
|---|---|---|
| 保存成功 | 下载报销单 PDF，选桌面 | 文件出现，能打开 |
| 取消 | 再下载一次，对话框点"取消" | 不报错，不留半个文件 |
| 重名覆盖 | 再下载一次，存同一个文件名，确认覆盖 | 覆盖成功，**旧文件没丢成 0 字节** |
| 不可写路径 | 存到 `C:\Windows\` | 有明确报错，程序不崩 |
| 批量 ZIP | 选多张报销单批量下载 | ZIP 里文件齐全 |
| 数据导出 | 数据维护 → 导出 | ZIP 能解开 |
| 备份 | 数据维护 → 创建备份 → 下载 | 能存下来 |
| 诊断包 | 数据维护 → 导出诊断包 | 能存下来，解开有 `diagnostics.json` |

### A6 数据迁移（需要你的旧便携目录副本）

**先恢复到 `clean` 快照重装**，让程序处于"没有 runtime 数据"的首次启动状态。

1. 先在宿主机上记下旧目录的基线数据，一会儿要对：

```powershell
# 数据库里各表行数
$db = "旧目录\data\expense.db"
# 附件文件数和总大小
(Get-ChildItem "旧目录\uploads" -Recurse -File | Measure-Object -Sum Length) | Select-Object Count, Sum
# 备份 ZIP 个数
(Get-ChildItem "旧目录\data\backups" -File).Count
```

2. 启动程序 → 引导页点**从旧便携版迁移**
3. 选中旧便携目录副本
4. 迁移完成后核对：

- [ ] 报销单数量与旧版一致
- [ ] 随便打开几张单，发票附件能正常预览（说明附件迁过来了）
- [ ] 数据维护里能看到旧的备份 ZIP
- [ ] 个性化设置（部门、出差人、补贴标准）保持原值
- [ ] 窗口大小位置沿用了旧的

5. 核对**不该迁的没迁**：

```powershell
dir "$env:LOCALAPPDATA\com.winloud.reimbursementtool\runtime"
```

不应该出现 `browser-profile`、`versions`、`current-version.json`、`portable-release.json`。

6. **核对旧目录没被动过**：比较迁移前后旧目录的文件数和总大小，应该完全一致。

7. **失败可重试**：恢复快照重装，迁移选一个**故意选错的目录**（比如桌面），应该明确报错且不留半个 runtime；再选对的目录，能正常迁移。

### A7 卸载重装不丢数据

1. 设置 → 应用 → 卸载"报销管理"
2. 确认数据还在：

```powershell
dir "$env:LOCALAPPDATA\com.winloud.reimbursementtool\runtime\data"
```

`expense.db` **必须还在**。

3. 重新装一遍，启动 → 应该**直接进业务界面**（不再问迁移），数据都在

### A8 OpenCV 兼容模式（可选）

需要 `opencv-wechat-runtime-opencv-*.zip`（宿主机执行 `scripts\build_opencv_runtime.ps1` 生成）：

1. 解压到 `%LOCALAPPDATA%\com.winloud.reimbursementtool\runtime\vendor\`
2. 个性化设置 → 发票二维码识别引擎 → 切到 OpenCV WeChatQRCode → 保存
3. 上传一张图片发票，能识别出金额

### A9 无 WebView2 环境（Win10 场景）

Win11 自带 WebView2，要测"缺 WebView2 自动安装"需要：

- 用 **Windows 10** 干净镜像（很多老版本不带 WebView2），或
- 在 Win11 上先卸载 "Microsoft Edge WebView2 Runtime"（设置 → 应用里找）

然后：

| 场景 | 期望 |
|---|---|
| 联网 + 常规包 | 安装过程自动下载装好 WebView2，程序能启动 |
| 断网 + 常规包 | 安装或启动失败，但**有明确提示**，不是静默白屏 |
| 断网 + 离线包 | 正常装好并启动（离线包自带 WebView2） |

> 离线包需要宿主机执行：
> `powershell -File scripts\build_tauri_release.ps1 -Version 2.0.0 -Offline`

## 阶段 B：需要正式签名密钥

### B1 生成正式密钥（在宿主机做，只做一次）

按 `docs/release-process.md` 的「updater 签名密钥」章节操作：生成密钥 → 把公钥填进
`tauri.conf.json` → 提交 → 备份私钥和密码。

### B2 构建两个版本

更新测试需要一个"旧版"和一个"新版"：

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY_PATH = "$env:USERPROFILE\.tauri\reimbursement.key"
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = "你的密码"

# 旧版
powershell -File scripts\build_tauri_release.ps1 -Version 2.0.0 -ReleaseDate 20260829
# 把产物另存一份
mkdir F:\update-test\v2.0.0
copy src-tauri\target\release\bundle\nsis\*  F:\update-test\v2.0.0\
copy dist-feed\*  F:\update-test\v2.0.0\

# 新版
powershell -File scripts\build_tauri_release.ps1 -Version 2.0.1 -ReleaseDate 20260829
mkdir F:\update-test\v2.0.1
copy src-tauri\target\release\bundle\nsis\*  F:\update-test\v2.0.1\
copy dist-feed\*  F:\update-test\v2.0.1\
```

> 构建 2.0.1 会改动 `Cargo.toml` / `tauri.conf.json` 的版本号，测完记得
> `git checkout src-tauri/Cargo.toml src-tauri/tauri.conf.json` 还原。

### B3 起一个本地 feed 服务

`tauri.conf.json` 的 endpoint 指向 GitHub。测试阶段不想真发 Release 的话，
临时把 endpoint 改成本机地址再构建旧版（这样旧版才会来问你的本地服务）：

```powershell
# 在 F:\update-test\v2.0.1 目录下起服务（把 latest.json 暴露出去）
cd F:\update-test\v2.0.1
python -m http.server 8000
```

虚拟机要能访问宿主机这个端口（VMware/VirtualBox 用桥接或 NAT 端口转发）。
`latest.json` 里的 `url` 也要改成这个地址下的安装包。

### B4 正向升级

1. 虚拟机恢复 `clean`，装 **2.0.0**，建些数据
2. 数据维护 → **检查更新** → 应该报告有 2.0.1
3. 点**安装更新**
4. 期望：自动下载 → 验签通过 → 安装 → **程序自动重启**，版本变成 2.0.1
5. 核对数据还在
6. 核对升级前备份已创建：

```powershell
dir "$env:LOCALAPPDATA\com.winloud.reimbursementtool\pre_update"
```

7. 重复升级 4 次以上，确认 `pre_update` 只保留**最近 3 份**

### B5 启动时自动检查（24h 逻辑）

程序把上次检查时间记在 WebView2 的 `localStorage` 里，不到 24h 不再查。
正式包关闭了开发者工具，改用清缓存目录的方式触发：

1. 完全退出程序
2. 删掉 WebView2 的数据目录（只清浏览器侧缓存，**不动业务数据**）：

```powershell
Remove-Item "$env:LOCALAPPDATA\com.winloud.reimbursementtool\EBWebView" -Recurse -Force
```

3. 重新启动 → 应该在界面上看到"发现新版本 2.0.1，可在数据维护页安装更新"的提示

> 如果目录名不是 `EBWebView`，先 `dir "$env:LOCALAPPDATA\com.winloud.reimbursementtool"`
> 看实际有哪些目录，除 `runtime` 和 `pre_update` 外的就是 WebView2 缓存。

### B6 签名篡改被拒绝

1. 把 `F:\update-test\v2.0.1\latest.json` 里的 `signature` 随便改几个字符
2. 虚拟机里检查更新 → 安装
3. **期望：明确报验签失败，拒绝安装，程序仍是 2.0.0 且能正常用**

### B7 不兼容数据结构被拒绝

1. 把 `F:\update-test\v2.0.1\data-compat.json` 改成：
   `{"min_data_schema_version": 99, "max_data_schema_version": 99}`
2. 虚拟机里检查更新
3. **期望：提示数据结构不兼容，不提供安装按钮**

## 出问题怎么办

1. 先看日志：`%LOCALAPPDATA%\com.winloud.reimbursementtool\runtime\logs\sidecar.log`
2. 导出诊断包（数据维护 → 导出诊断包），里面有版本、路径、环境信息
3. 记下：哪一步、期望什么、实际什么、日志里的报错原文
4. 恢复快照重来一次，确认是否稳定复现
