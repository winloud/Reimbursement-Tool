### 构建链路（阶段 7 产物首次端到端实跑）

- SHA256：`a974b5c9e630f9d6ef690943893828880ab715e138c40167eab18ad2743889ce`

### sidecar 打包布局（生产启动的关键路径）

修复嵌套与前缀缺陷后重跑构建，实测确认三者对齐：

| 环节 | 路径 |
|---|---|
| 装入点 | `src-tauri/resources/reimbursement-sidecar/reimbursement-sidecar.exe` |
| 打包后（resource_dir 下） | `resources/reimbursement-sidecar/reimbursement-sidecar.exe` |
| `sidecar.rs` 解析 | `resources` + `reimbursement-sidecar` + `reimbursement-sidecar.exe` |

已加单测把 `sidecar.rs` 的路径常量与 `tauri.conf.json` 的 `bundle.resources` 对拍，
防止两边再次错位。

### 签名与 updater feed 链路（用一次性测试密钥）

用 `cargo tauri signer generate` 生成的**测试密钥**（存放于仓库外的
`%USERPROFILE%\.tauri\test-signing\`）临时替换 `tauri.conf.json` 的 pubkey 实跑，
验证完毕后已还原为正式公钥并逐字节核对一致。

- `cargo tauri signer sign` 产出 `.sig`（内容为 base64 编码的 minisign 签名）
- `generate_updater_feed.ps1` 产出 `latest.json` + `data-compat.json`
- 两个 feed 文件均为**无 BOM** UTF-8，按 `serde_json` 的严格规则可解析
- `latest.json` 的 `signature` 与 `.sig` 文件逐字一致
- `validate_tauri_release.ps1` 全项校验通过

> 未覆盖：客户端真实验签与安装。测试密钥与正式公钥不配对，正向升级路径仍需正式私钥，
> 见 4.5 节。

## 三、阶段 9 实跑发现并修复的缺陷

首次实跑构建即暴露 6 个缺陷，全部只在**正式发布路径**上触发，自动化测试与开发模式都不会命中。

| # | 缺陷 | 后果 | 修复 |
|---|---|---|---|
| 1 | sidecar 装入点多一层嵌套（`Copy-Item -LiteralPath <dir> -Destination <已存在dir>`） | 安装包内路径错位 | 改为复制目录内容，并加布局断言 |
| 2 | `sidecar.rs` 解析路径漏掉 Tauri 保留的 `resources/` 前缀 | 与 1 叠加后，**生产安装包永远找不到 sidecar，静默回退 `python sidecar_app.py`；终端用户无 Python，表现为启动即失败** | 补 `resources` 段，并加与 `tauri.conf.json` 对拍的单测 |
| 3 | 版本同步用「替换前后内容是否相同」判断字段存在 | 版本号已等于目标值时误报「找不到 version 字段」，同一 tag 重建构建（`workflow_dispatch` 的主要用途）必失败 | 改用 `-notmatch` 做存在性判断 |
| 4 | `Invoke-Step` 检查 `$LASTEXITCODE`，但纯 PowerShell 步骤从不设置它 | 首个纯 PS 步骤即因 `$null -ne 0` 误判失败，构建无法开始 | 进入步骤前归零 |
| 5 | `generate_updater_feed.ps1` 用 `Set-Content -Encoding UTF8` 写 feed | PowerShell 5.1 的 `utf8` 带 BOM，而 `serde_json` 在第 1 列拒绝 BOM，**所有客户端的更新检查都会失败** | 改写无 BOM UTF-8 |
| 6 | `validate_tauri_release.ps1` 断言 `.sig` 以明文 `untrusted comment:` 开头 | Tauri 写出的 `.sig` 是 base64，校验必然失败，发布前门禁形同虚设 | 先 base64 解码再判断，并新增 feed 与 `.sig` 一致性校验 |

另有一组中文 Windows 专有的编码缺陷已在阶段 8 修复（PowerShell 脚本缺 UTF-8 BOM、
`gh` 输出按 OEM 代码页解码、`SHA256SUMS.txt` 写成 ASCII 丢中文包名），详见 CHANGELOG。

**共性教训**：本项目产物名与配置含中文，且发布链路全在 PowerShell 上，
凡「读文件 / 写文件 / 读子进程输出」都必须显式指定 UTF-8，不能依赖默认值。

### 开发机环境注记（非产品缺陷）

本机 `PSModulePath` 被 PowerShell 7 的路径挤占，Windows PowerShell 5.1 下
`Get-FileHash` 不可用。`validate_tauri_release.ps1` 已改用 .NET SHA256 实现规避
（与 `validate_release_asset.ps1` 一致）。`publish-release.yml` 仍使用 `Get-FileHash`，
在 GitHub Actions 的干净 `windows-latest` 上正常，未改动。
